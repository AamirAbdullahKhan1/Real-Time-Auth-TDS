# Run Ironclad locally

1. Create an empty PostgreSQL lab database. Apply the baseline with `psql -d ironclad -v ON_ERROR_STOP=1 -1 -f backend/schema.sql` using credentials authorized for that database. For an existing database, compare the existing column types and constraints with the baseline before applying it.
2. Configure `backend/.env` using `backend/.env.example`. The example disables database TLS for loopback development. Use certificate verification for a remote database.
3. From `backend`, run `npm ci` and `npm start`. From `frontend`, run `npm ci` and `npm run dev`. Vite reads `PORT` from `backend/.env` and forwards `/api` to that port on localhost. Both default to 3000 when unset. Set `IRONCLAD_API_TARGET` in `frontend/.env` or the Vite process environment to override the proxy target. Restart Vite after changing either setting. If the proxy reports ECONNREFUSED, check the Express terminal first. Express listens only after connecting to PostgreSQL. For ENOTFOUND, compare the hostname in `DATABASE_URL` with the connection string in the Neon dashboard and check DNS on the backend machine.
4. Register a lab account, enter its emailed code, sign out, try an incorrect password, then sign in and enter the new code. An outstanding code triggers a 60-second cooldown. After a successful verification, you can sign out and sign in immediately, subject to the hourly limit. The activity page should show the account's registration, logout, login failure and login success. The local JSON Lines file is `backend/logs/auth-events.jsonl`.

Email verification is required after registration and every password login. Apply backend/migrations/002_email_mfa.sql to an existing database after the session migration. Set RESEND_API_KEY and OTP_FROM_EMAIL in backend/.env and restart Express. OTP_FROM_EMAIL is the sender identity, for example "Ironclad <no-reply@your-verified-domain.example>". Set it once using a domain verified for sending in Resend. The app automatically sends each code to the account email address. Existing users keep their passwords and verify their address on their next login. Sessions created before email verification was introduced require a fresh login. Verified sessions last up to 24 hours and are revoked on sign-out. For a production frontend build, route `/api` to Express through the same origin, or configure `VITE_API_BASE_URL` and the backend's `FRONTEND_ORIGIN`.

Set `SPLUNK_HEC_ENABLED=true` with the HEC event endpoint and token to forward newly recorded lab events. Search for `source="ironclad-auth"` in the index allowed by the token. PostgreSQL remains the audit source of record. HEC delivery is best effort and does not replay past events.
